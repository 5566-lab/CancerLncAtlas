Local-CNV statistical patient scopes
===================================

The native association/validation reconstruction now observes the actual
patient masks used by the original statistical functions. It does not fit
a neural or LASSO model, change statistical formulas, or run a real cohort.
All numerical execution and verification belong on host 149.

Scope and observation units
---------------------------

``local_cnv_patient_scopes_private`` is a private model-use table. Each row
describes a shared patient cohort and a group of candidate pairs, rather than
expanding one row per patient per pair. ``patient_fold_id`` is the outer
model fold. Train cohorts exclude that fold and its adjacent validation fold;
validation cohorts use only (outer fold + 1) modulo 5. Original source-file
exposure records remain present because normalization and other upstream
transformations can use populations wider than an individual association.

* ``A0_FULL``: the original expression/activity patient intersection, without
  requiring CNV presence. The original column-mean then zero imputation is
  preserved. Both train and adjacent-validation A0 calculations are recorded.
  It is not a claim that every value in that cohort was measured.
* ``MATCHED_SHARED_COVARIATE_DESIGN``: the common patient population used to
  construct the shared covariate design before pair-specific complete-case
  filtering. Imputation and design construction can depend on these patients
  even when a particular pair subsequently excludes them.
* ``A0_MATCHED_A1_LOCAL``: finite expression, activity, local signed CNV and
  design rows with local CNV callability. A measured neutral CNV value of zero
  remains eligible. Missing local CNV does not become a neutral measurement.
* ``A1_ON_A2_A2_LOCAL_PATHWAY``: the preceding mask further restricted by
  pathway CNV callability and finite pathway CNV. This is the exact smaller
  population for both A2 and its own A1 comparator. It does not replace the
  primary A1 cohort. The validation producer records its A1 computation only.
* ``G0_CALLABILITY_SCREEN``: each original lncRNA group sharing a local-CNV
  callable cohort, before the 40-patient graph threshold.
* ``G0_VARIANCE_SCREEN``: the cohort and input feature sets on which the
  original variance filters run. Features failing those filters remain
  represented at this screening stage.
* ``E0_E1_TESTED_CARTESIAN``: the retained lncRNAs crossed with the retained
  genes actually passed to both edge calculations. This includes candidates
  that lose later significance/top-k selection. Original median/zero
  imputation and one-sided local-CNV correction are unchanged.

Pairs, availability and identity
--------------------------------

``pairing=ALIGNED_PAIRS`` means position i of ``lncrna_ids_json`` is paired
with position i of ``target_ids_json``. ``pairing=CARTESIAN`` means every
listed lncRNA is crossed with every listed gene. ``candidate_pair_count``
records that interpretation without materializing the product. A missing
expression/pathway feature has an explicit zero-patient, unentered matched
scope; it is not silently assigned the full common cohort.

``calculation_entered`` distinguishes a cohort that reached the calculation
from one rejected by its patient-count gate. For graph callability screening
it records whether the cohort passed the 40-patient gate; a later variance
screen can still prevent edge calculation. ``finite_statistic_json`` stores
aligned finite/estimable flags from the original pair result, or null when
the event describes shared design/screening/Cartesian scope. Passing a
patient-count threshold does not imply a finite or available association.
These fields describe statistical input use, not an optimizer update,
neural gradient, published model score or independent biological validation.

``patient_map_row_indices_json`` contains zero-based row positions in the
hash-bound original patient map, not patient IDs. ``native_patient_count``
counts distinct identifiers after the original canonicalization. Several
source rows can correspond to one such identifier. ``cohort_id`` binds the
patient-map hash and exact row set. These records also bind the actual
consumed output, source release, cancer, model, dependency context and role.

Patient identity reconciliation still requires an explicit file-qualified
crosswalk. It uses the original raw identifiers at those source row
positions, not an invented mapping for their normalized strings. Private
patient tokens and public mapping counts are generated by the existing
PatientUse path. Unmapped aliases remain unmapped; canonicalization alone
does not assert cross-study biological identity. Test/OOF patients, unknown
native identities and duplicate identities in one cohort are rejected.

Consumption, privacy and limitations
------------------------------------

The actual local-CNV model-source inspector captures scopes while its
existing numerical replay compares every output column and metadata field.
A numeric-only cache entry cannot manufacture a missing patient trace.
Captured scopes can be reused in another dependency context only after
current source/output bytes, code and validation parents are verified again.
The private scope table is rebuilt by normal model-use recomputation.

Model-use serialization marks the table private and its loader rejects a
missing/false private flag. Current external evaluation does not publish
this table; it retains only the existing public mapping/overlap summaries.
Detailed cohort row references, aligned pairs and Cartesian definitions stay
in the private inventory. Source inspection does not remove the earlier raw
segment/reference/acquisition and cross-module identity limitations.

This closes the local-CNV statistical row-scope reconstruction boundary. It
does not close State-core dependencies, all other module-specific patient
scopes, raw assay ancestry or final external-validation acceptance. Original
historical receipts without numerical replay keep their explicit unresolved
row-level ancestry gap.

Implementation: ``local_cnv_patient_use.py``, ``local_cnv_source_replay.py``,
``local_cnv_confounding.py``, the original association/validation scripts and
``current_model_use.py``. Synthetic verification includes actual native
workers/closeout, exact masks and counts, private serialization and explicit
file-qualified alias mapping; no real scientific analysis is claimed.

## 1. The four modes

Generated by `scripts/phase11_generate_ablations.py` into
`config/rbp_ablation/<mode>.yaml`. The modes differ **only** on the
`rbp_evidence` switches.

| switch | A | B | C | D |
|---|---|---|---|---|
| `preserve_assay_type` | · | T | T | T |
| `typed_binding_relations.enabled` | · | T | T | T |
| `typed_binding_relations.include_predicted` | · | · | · | · |
| `encode_eclip.enabled` | · | · | T | T |
| `encode_rbp_kd.enabled` | · | · | · | T |
| `encode_rbp_kd.primary_graph` | · | · | · | · |
| `encode_rbp_kd.evidence_only` | T | T | T | T |
| `rbns.enabled` | · | · | · | · |
| `changes_primary_ranking` | · | · | · | · |
| `auxiliary_gradients_into_core` | · | · | · | · |
| `rbp_kd_is_lncrna_function_truth` | · | · | · | · |

* **A `legacy_generic_binding`** — the historical flat `binds_protein` relation;
  reproduces the pre-change model exactly (proven in the Phase 3 report §4).
* **B `typed_binding_only`** — assay typing preserved, no ENCODE.
* **C `typed_binding_plus_encode_eclip`** — B plus ENCODE eCLIP.
* **D `full_rbp_evidence`** — C plus RBP knockdown in the Evidence layer only.

`include_predicted` is **false in every mode**. Real data shows 84.2 % of typed
lncRNA–RBP relations are sequence-based predictions; admitting them by default
would present ~773k predictions as measurements. A separate, explicitly labelled
`typed_binding_plus_predicted` variant is available for a reviewer who wants to
measure their contribution — it is deliberately **not** one of the four headline
modes.

## 2. Fairness is enforced in code

The plan requires: *相同 patient folds / 相同 candidate universe / 相同 LASSO base /
相同 label / 相同 random seeds / 相同训练预算*, and forbids changing other
modalities to help a result.

`assert_fair_comparison()` compares every mode against mode A on exactly those
axes and raises otherwise. The axes are bound to **real artifacts**, not
placeholders:

| axis | bound value |
|---|---|
| `seed` | `20260726` (mirrors `patient_fold_authority.DEFAULT_SEED`) |
| `n_folds` | `5` (mirrors `patient_fold_authority.N_FOLDS`) |
| `candidate_universe_sha256` | `cced638f…071f` (mirrors `evidence_training.FORMAL_CANDIDATE_SHA256`) |
| `lasso_base_sha256` | `6c1cd82c…b066` |
| `patient_fold_manifest_sha256` | `e05c2008…e253` (mirrors `FROZEN_V32_SAMPLE_PATIENT_MAP_SHA256`) |
| `label_definition` | `V32_FORMAL_STRONG_PLUS_WEAK_POSITIVE` |
| `training_budget_epochs` / `learning_rate` / `batch_size` | `40` / `2.0e-3` / `128` |
| `evaluation_metric` | `AUPRC` |

Tests assert each bound value equals the authoritative constant in the real
module, so drift between the ablation config and the training code is caught
rather than assumed away.

### The LASSO baseline is reused, never recomputed

Per instruction, the existing baseline is fingerprinted rather than
re-materialised:

```
${PRIVATE_WORK_ROOT}/CancerLncAtlas/results/v3_state_formal_runs/
  V3STATE-formal500-20260810T101223Z-a8803782dcf0_server_handoff/run/posttraining_lasso_full
```

8 files, 25 MB. `manifests/LASSO_BASE_MANIFEST.tsv` records each leaf SHA256;
`lasso_base_sha256` is the SHA256 over the sorted `"<sha256>  <name>\n"` lines.
Every mode shares that one digest, so "same LASSO base" is a verifiable fact.

### Mode-independent invariants

`assert_fair_comparison()` also rejects any mode that sets
`changes_primary_ranking = true`, `auxiliary_gradients_into_core = true`,
`rbp_kd_is_lncrna_function_truth = true`, or tries to put RBP knockdown into the
primary graph. A mode that cheats on the science cannot be constructed, let alone
run.

## 3. What each mode is expected to isolate

| comparison | isolated question |
|---|---|
| **B − A** | does preserving assay identity change anything at all? |
| **C − B** | does ENCODE eCLIP add information beyond curated CLIP evidence? |
| **D − C** | does RBP knockdown, as Evidence-only mechanistic support, add anything? |
| **C vs shuffled eCLIP** | is any gain from real pairing rather than added degree? |

## 4. Required reporting (pre-specified, per Phase 13)

Committing to the metric set **before** seeing results, so the analysis cannot be
reshaped around whatever comes out.

### 4.1 Primary task

For every mode, and for the reused LASSO base:

* AUPRC, AUROC, Precision@K, calibration (reliability curve + ECE);
* **ΔAUPRC vs LASSO** as the headline number;
* per-fold values, not just the pooled mean, so fold variance is visible.

### 4.2 RBP modality contribution

* `typed` vs `legacy` (B − A);
* `ENCODE` vs `no-ENCODE` (C − B);
* **real eCLIP vs shuffled eCLIP** — the shuffle preserves node count and roughly
  the degree distribution but destroys real lncRNA–RBP pairing. If C is not
  clearly better than its shuffle, the honest conclusion is that the gain came
  from added edges, not from biology.

### 4.3 Evidence layer

* confidence calibration;
* held-out evidence performance;
* per-assay-subtype performance (eCLIP, other CLIP, RIP, rna capture,
  experimental-unspecified, predicted).

### 4.4 Candidate explanation — with a mandatory disclaimer

Top-K composition by supporting assay is reported, **but ENCODE eCLIP is training
input in modes C and D and therefore cannot also be presented as independent
external validation.** Any table that mixes the two must carry that disclaimer.

### 4.5 RBP knockdown is orthogonal support, not validation

RBP KD enters only the Evidence layer in mode D. If reported, it must be labelled:

> **RBP-level functional support** — the perturbation was applied to the RBP, not
> to the lncRNA. This is **not** lncRNA perturbation validation and must never be
> described as such.

The `rbp_kd_is_lncrna_function_truth` invariant exists precisely to make that
misstatement unconstructible.

## 5. Pre-registered decision rule

Stated in advance to prevent post-hoc rationalisation:

* If **C ≤ B + noise**, ENCODE eCLIP does not help. Report **FAIL** and say so.
* If **C ≈ shuffled eCLIP**, any gain is degree, not biology. Report **FAIL**.
* If **D ≤ C**, RBP knockdown adds nothing beyond eCLIP. Report it as such.
* **No weight may be tuned, no label changed, and no mode may be redefined to
  convert a FAIL into a PASS.** The plan's prohibition is absolute: *"若没有增益，
  必须如实返回 FAIL，不得提高权重或修改标签追结果."*
